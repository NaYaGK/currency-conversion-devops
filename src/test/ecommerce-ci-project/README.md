## CI Lifecycle Workflow

Developer -> Code -> Commit & Push -> Jenkins Pipeline -> Production

### Phase 1: Developer writes code
You write a new feature (e.g., add a new endpoint in OrderController.java).

### Phase 2: Compile and Unit Test

Command:
  mvn clean test

What happens:
- Maven compiles all .java files into .class files
- Runs all 3 test cases in OrderServiceTest.java
- JaCoCo generates a code coverage report at target/site/jacoco/index.html
- If any test fails, the build STOPS

Jenkins pipeline stage:
  stage('Test') {
      steps { sh 'mvn clean test' }
      post { always { junit 'target/surefire-reports/**/*.xml' } }
  }

### Phase 3: Package the Application

Command:
  mvn clean package -DskipTests

What happens:
- Compiles code and bundles into target/order-service-1.0.0-SNAPSHOT.jar
- -DskipTests skips tests (already ran them in Phase 2)

### Phase 4: Build the Docker Image

Command:
  docker build -t ecommerce-api:1 .

Multi-stage magic:
- Stage 1 (builder): Full Maven + JDK image compiles code inside Docker
- Stage 2 (runtime): Tiny Alpine + JRE image copies ONLY the JAR
- Result: Small, clean, secure image with no source code or build tools

### Phase 5: Security Scan

Command:
  trivy image --severity HIGH,CRITICAL --exit-code 1 ecommerce-api:1

What happens:
- Trivy scans for known CVEs
- --exit-code 1 fails the build if any HIGH/CRITICAL found
- jackson-databind:2.12.7.1 is intentionally vulnerable - practice finding and fixing it!

### Phase 6: Run the Container

Command:
  docker run -d -p 8080:8080 --name order-app ecommerce-api:1

Test the API:
  # Create a new order
  curl -X POST http://localhost:8080/api/orders \
    -H "Content-Type: application/json" \
    -d '{"productName": "Laptop", "quantity": 2, "price": 60.0}'

  # Get all orders
  curl http://localhost:8080/api/orders

  # Update an order status
  curl -X PUT "http://localhost:8080/api/orders/1/status?status=SHIPPED"

## API Endpoints

| Method | URL                        | Description           |
|--------|----------------------------|-----------------------|
| POST   | /api/orders                | Create a new order    |
| GET    | /api/orders                | Get all orders        |
| PUT    | /api/orders/{id}/status    | Update order status   |

Business Rule: If price x quantity > $100, a 10% discount is automatically applied.

## Full CI/CD Pipeline - Learning Guide (Hints Only!)

This section guides you through building a real Jenkins pipeline step by step.
You do the work, use these hints when you get stuck!

### Pipeline Flow (What You Are Building)

  Code Commit
      |
      v
  Stage 1: mvn validate         <-- Is the pom.xml valid?
      |
      v
  Stage 2: mvn clean test       <-- Do all tests pass?
      |
      v
  Stage 3: SonarQube Analysis   <-- Is the code quality good? (FAIL = STOP)
      |
      v
  Stage 4: mvn package          <-- Create the .jar file
      |
      v
  Stage 5: JFrog Artifactory    <-- Upload .jar to artifact repository
      |
      v
  Stage 6: Docker Build         <-- Build image from Dockerfile
      |
      v
  Stage 7: Trivy Scan           <-- Any HIGH/CRITICAL CVEs? (FAIL = STOP)
      |
      v
  Stage 8: Push to DockerHub    <-- Only if Trivy passed!

### Stage 3: SonarQube Code Quality Gate - Hint
Goal: Send your code to SonarQube and STOP the pipeline if quality fails.
- First: Create a token in SonarQube (My Account > Security > Generate Token)
- Second: Store that token in Jenkins (Manage Jenkins > Credentials)
- In your Jenkinsfile, the command is: mvn sonar:sonar -Dsonar.host.url=...
- After the scan, Jenkins must WAIT for SonarQube to compute the Quality Gate
  Hint: Use the step called "waitForQualityGate()" in your pipeline

---

### Stage 4: Package the JAR - Hint
Goal: Produce the final .jar file that will go into Docker.
- You already did this manually. What flag do you add to skip tests?
  Hint: -D_______Tests
- After this, your JAR lives at: target/order-service-1.0.0-SNAPSHOT.jar

---

### Stage 5: JFrog Artifactory - Hint
Goal: Upload the .jar to JFrog so it is versioned and stored safely.
- In Jenkins, configure JFrog server URL under: Manage Jenkins > Configure System
- In your Jenkinsfile, use the "rtUpload" or "jf rt upload" command
- You need to create a LOCAL repository in JFrog first (type: Maven)
- Think of JFrog like a "Google Drive" for your compiled .jar files

---

### Stage 6: Docker Build - Hint
Goal: Build a Docker image using the Dockerfile in your project.
- The command you used before was: docker build -t name:tag .
- In Jenkins, use the BUILD_NUMBER variable to auto-tag: ecommerce-api:${BUILD_NUMBER}
- Remember: Jenkins must have permission to run Docker commands
  Hint: Add the jenkins user to the docker group on EC2

---

### Stage 7: Trivy Scan - Hint
Goal: Scan the Docker image. FAIL the build if HIGH or CRITICAL CVEs are found.
- You already know this command from earlier practice!
- Hint: trivy image --severity ____,_______ --exit-code _ image:tag
- The intentionally old jackson-databind version WILL fail this stage.
  To pass: find it in pom.xml and upgrade to a newer version, then rebuild.

---

### Stage 8: Push to DockerHub - Hint
Goal: Push the scanned, clean image to DockerHub.
- First: Store your DockerHub credentials in Jenkins (Manage Jenkins > Credentials)
  Use type: Username and Password, ID: dockerhub-creds
- In Jenkinsfile, use withCredentials block to login safely:
  Hint: docker login -u $USERNAME -p $PASSWORD
- Then: docker push yourusername/ecommerce-api:${BUILD_NUMBER}

---

### post { always { } } Block - Hint
After all stages finish (pass or fail), Jenkins should clean up the local Docker image.
- Why? Every build creates a new image. Without cleanup, disk fills up fast!
- Hint: docker rmi image:tag
  Add "|| true" at the end so the pipeline does not fail if the image was never created.

### Common Mistakes to Avoid

1. Jenkins cannot run Docker? -> Add jenkins user to docker group: sudo usermod -aG docker jenkins
2. SonarQube Quality Gate times out? -> Check waitForQualityGate(abortPipeline: true)
3. JFrog upload fails? -> Did you create the repository in JFrog first?
4. Trivy fails? -> Good! That means it found vulnerabilities. Fix pom.xml and rebuild.
5. DockerHub push fails? -> Check if credentials ID in Jenkinsfile matches Jenkins credentials ID
